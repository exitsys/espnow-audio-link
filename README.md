# espnow-audio-link

两块 ESP32-S3 之间的无损无线音频链路。发射端插在电脑或电视盒子上，枚举成一个 **USB 声卡**；接收端用 **I2S 接 PCM5102A**，输出给功放或有源音箱。

不压缩、不重新编码、不经过蓝牙协议栈 —— 用 ESP-NOW 直接发 48 kHz / 16 bit 的原始 PCM。

```
┌──────────┐   USB Audio Class 2   ┌──────────┐        ESP-NOW         ┌──────────┐   I2S    ┌──────────┐
│ PC / 盒子 │ ───────────────────▶ │ TX: S3   │ ───────────────────▶  │ RX: S3   │ ───────▶ │ PCM5102A │
│          │   48k/16bit/2ch       │ USB 声卡 │  960B/包 · 200 包/秒    │ 抖动缓冲 │  3 线    │  → 功放  │
└──────────┘                       └──────────┘   11Mbps · 硬件 ACK    └──────────┘          └──────────┘
```

## 为什么不用蓝牙

| | 蓝牙 SBC / AAC | 本项目 |
|---|---|---|
| 编码 | 有损压缩 | 原始 PCM，无压缩 |
| 采样率 | 44.1 kHz | 48 kHz |
| 延时 | 150~300 ms（协议栈缓冲不可控） | **约 95 ms**（设备侧，可复现） |
| 时钟 | 受对端缓冲策略影响 | 收发各自晶振，水位闭环吸收漂移 |

代价是没有通用性：两端都是 ESP32，需要自己焊三根线。

## 实测指标

| 项 | 值 |
|---|---|
| 格式 | 48 kHz / 16 bit / 2ch |
| 码率 | 192 KB/s（1.536 Mbps） |
| 包长 / 包率 | 960 字节 / 200 包每秒（5 ms 一包） |
| 无线 | ESP-NOW 单播，11 Mbps 固定速率，硬件 ACK，信道 11 |
| 抖动缓冲 | 容量 48 包（240 ms），稳态 15 包（75 ms） |
| **设备侧延时** | **约 95 ms** = 队列 75 + DMA 15 + 空口/拼包 5 |
| 端到端（接 PC） | 约 120 ms（+ WASAPI 25 ms、USB 2 ms） |
| 稳态表现 | 连续 100 秒：欠载 0、补位 0、波形跳变 0、重采样 0.00% |
| 静音期间 | 发射端补位包 200 包/秒，接收端欠载 0（2026-11-25 上板实测；改动前是 166 包/秒、每秒欠载 33 次） |
| 重采样 | 32 抽头多相 sinc，稳态精确直通（零插值） |

## 工作原理

1. **TX** 把 USB 声卡收到的 PCM 按 240 帧（5 ms）拼成一个包，凑满才发，最多等 30 ms
2. **ESP-NOW** 单播发到接收端，每包有硬件 ACK，发送回调直接给出逐包成败
3. **RX** 收到的包进 48 包环形队列（抖动缓冲），播放任务按需取出
4. 出队后过 **32 抽头重采样 → 电平校准 → TPDF 抖动 → I2S**，写进 DMA 播放

## 关键设计

### 1. 不压缩

960 字节正好是 5 ms 的 48k/16bit 立体声。压缩能省带宽，但 ADPCM 一类有损编码在安静段落能听出量化噪声；而 11 Mbps 发 1.5 Mbps 绰绰有余。**用带宽换音质，在这个场景里是划算的。**

### 2. 重采样只在必要时工作

接收端的 I2S 时钟跟随音源采样率，让重采样比例精确等于 1.0。此时 `src_process` 全走整数帧直取分支（每帧 2 载 2 存），**一个插值样本都不产生**。

比例一旦偏离 1.0 哪怕 0.01%，包边界就得拿插值样本顶替，残差从 −96 dB 掉到 −30 dB —— 单件乐器、小电平的钢琴和小提琴会明显发糊。

所以水位闭环带 **3.0 包死区**：队列在目标 ±3 包内一律不调，宁可少省 15 ms 延时，也要让插值器彻底停下。

### 3. 水位闭环 + 相位跨包连续

收发两端晶振必然有几十 ppm 差异，队列会缓慢漂移。做法是队列深度做 EMA，偏离死区就给重采样比例加一个小偏置（P 控制，增益 8，上限 ±0.3%），连续调节、没有离散突变点。

重采样相位**跨包连续**：包尾的小数相位原样留给下一包，并允许相位为负（回落到 32 帧历史区）。若每包把相位吸附到整数帧，等于 200 次/秒的时间轴硬跳变 —— 1 kHz 只差 −44 dB 听不出，10 kHz 以上就是几十度相位突变。

### 4. 丢包用 PLC 复读，不用补零

丢包时重复上一包并按 1.00 / 0.60 / 0.35 / 0.20 衰减，最多 4 包。补零是波形阶跃到 0，功放会给出宽频冲击（"咔"）；复读频谱连续，听感上是短暂发糊而不是爆音。

### 5. 所有不连续点都做淡化

| 场合 | 处理 |
|---|---|
| 接缝（PLC 续接、漂移丢包） | 2 ms 交叉淡化：从上一段尾部渐变到新数据 |
| 断流恢复（缺口 > 20 ms） | 15 ms 线性淡入：从静音升到满幅 |
| 静音恢复（主机保持流但送全零） | 连续 3 包全零后出现内容 → 同样 15 ms 淡入 |
| 切换采样率 / 重配 I2S 时钟 | 先按 6 包（30 ms）把真实音频淡出到 0，再 disable/enable，恢复后 15 ms 淡入 |
| 主机暂停、换轨 | TX 侧补位段按 Q8 包络约 5 ms 淡出，恢复供数后约 2.7 ms 淡入 |

时钟重配这一步尤其关键：`i2s_channel_reconfig_std_clock()` 必须先把通道停掉，而 DMA 里通常还压着 10~15 ms 已写入的音频。直接停等于把波形从中间砍断，听感就是一声闷响 —— 所以要先淡出，让切点落在静音上。

### 6. 其他

- **TPDF dither**：±1 LSB 三角分布，压掉 16 bit 截断的相关失真
- **电平校准**：PCM5102A 满刻度 2.1 Vrms，对有源音箱是结构性过载，输出前统一压一层（`ALINK_OUT_ATTEN_DB`）
- **音量**：主机的 USB 音量请求映射到 −50~0 dB（51 档），在**一包内线性插值**完成，逐样本连续，拖动不滞后

## 目录结构

| 路径 | 内容 |
|---|---|
| `tx_uac/` | 发射端：USB UAC2 声卡 → ESP-NOW（含 vendored 的 `usb_device_uac` 组件） |
| `rx_uac/` | 接收端：ESP-NOW → 抖动缓冲 → 重采样 → I2S |
| `components/alink_common/` | 两端共享：包头、包长、信道、缓冲与淡化参数 |
| `legacy/` | 旧版链路（ADPCM + UDP），仅作设计对照，不维护 |
| `TUNING.md` | 参数档位对照、每个参数的副作用、踩过的坑 |

固件体积：RX 752 KB、TX 781 KB，均为默认 `SINGLE_APP` 分区（1 MB app / 4 MB flash）。

## 硬件

**接收端**

| PCM5102A | ESP32-S3 |
|---|---|
| BCK | GPIO10 |
| LRCK | GPIO11 |
| DIN | GPIO12 |
| SCK | **GND**（DAC 用内部 PLL 从 BCK 恢复时钟） |
| VIN / GND | 5 V / GND |

本版不输出 MCLK。若想给 DAC 更强的参考时钟，把 `ALINK_I2S_USE_MCLK` 设为 1，SCK 改接 GPIO13（12.288 MHz）。

**发射端**：任意带原生 USB 的 ESP32-S3（USB 走 GPIO19/20），插上主机后枚举为 `usb uac` 声卡。

两块板均为 4 MB flash、240 MHz。

## 构建

需要 ESP-IDF v5.5（仓库在 v5.5.6 上验证）。

```bash
. $IDF_PATH/export.sh          # Windows 用 export.ps1 / idf_cmd_init.bat

cd rx_uac && idf.py set-target esp32s3 build flash
cd ../tx_uac && idf.py set-target esp32s3 build flash
```

### 配置接收端地址

发射端要知道接收端的 MAC，用 menuconfig 配，不用改代码：

```bash
cd tx_uac && idf.py menuconfig
# Component config → Audio link → 接收端 MAC 地址
```

接收端上电时串口会打印自己的 MAC：

```
W (210) alink_rx: ESP-NOW 就绪：本机 84:c7:bb:5a:73:94 信道 11，等发送端的单播包（不校验发送方）
```

抄过去即可。接受 `aa:bb:cc:dd:ee:ff`、`aa-bb-...` 和 12 位无分隔符三种写法；少一位、多一段、某段超过 FF 都算格式不对，这时固件会打印错误并退回内置默认值，不会悄悄解析成另一个地址。

### 限定发送端（可选）

默认情况下接收端来者不拒：任何设备只要往它的 MAC 发音频帧都会被播放。要只认自己的发射端，
在接收端把发射端的 MAC 填进 menuconfig：

```bash
cd rx_uac && idf.py menuconfig
# Component config → Audio link → 发射端 MAC 地址
```

发射端上电时串口会打印 `本机 xx:xx:...`。写法和上面一样；留空（默认）就是不校验，
填了但格式不对时固件会打印错误并照常不校验，不会因此没声音。

## 适用边界

- **一对一的单播链路**：没有配对流程，靠 MAC 识别对端；不支持一对多或漫游
- **48 kHz / 16 bit 固定格式**：声卡只向主机声明 48 kHz 这一个采样率，44.1 kHz 的音源由主机（Windows / Android 的混音器）重采样成 48 kHz 再送过来，链路本身不会遇到 44.1 kHz。接收端的 I2S 时钟跟随针对的是「非标准的 48k」—— 比如实测送 47.93 kHz 的电视盒子：连续两个 30 秒窗口测出差 60 Hz 以上才重配，期间有 30 ms 淡出 + 15 ms 淡入（听感上是一次极短的停顿）
- **无加密**：ESP-NOW 明文单播，同信道且知道 MAC 的设备可以抓包，只适合自家局域网环境。接收端可以在 menuconfig 里填发射端 MAC 做白名单，挡住别的设备往音箱里灌音频（见「限定发送端」）；白名单不加密，同信道的设备仍然能听到音频
- **固定信道，受周围 WiFi 影响**：ESP-NOW 和别的网络抢同一个信道的空口。相邻信道上有强信号、或者有人在大量传数据时，帧会排在发射端的驱动里发不出去，听感是几秒的卡顿后自行恢复（详见 TUNING.md 坑 13）。想知道周围的占用情况，把 `rx_uac/main/alink_rx.c` 里的 `ALINK_WIFI_SCAN` 设为 1 烧一次，接收端启动时会把每个信道上的 AP 列出来，看完改回 0
- **只在 ESP32-S3 上验证**：C3 单核 160 MHz 理论上能跑同一套算法（这段代码最早就是在 C3 上写的），但本版有 4 处 S3 硬编码（时钟源、核绑定、引脚、目标芯片），未做适配
