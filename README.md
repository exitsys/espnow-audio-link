# espnow-audio-link

两块 ESP32-S3 之间的无损无线音频链路。发射端做成一个 **USB 声卡**插在电脑或电视盒子上，接收端用 **I2S 接 PCM5102A** 输出到功放。

不压缩、不丢帧、可听不出无线存在 —— 用 ESP-NOW 直发 48kHz/16bit 原始 PCM。

```
┌──────────┐   USB Audio Class 2   ┌──────────┐        ESP-NOW         ┌──────────┐   I2S    ┌──────────┐
│ PC / 盒子 │ ───────────────────▶ │ TX: S3   │ ───────────────────▶  │ RX: S3   │ ───────▶ │ PCM5102A │
│          │   48k/16bit/2ch       │ USB 声卡 │  960B/包 · 200 包/秒    │ 抖动缓冲 │  3 线    │  → 功放  │
└──────────┘                       └──────────┘   11Mbps · 硬件 ACK    └──────────┘          └──────────┘
```

## 关键指标（实测）

| 项 | 值 |
|---|---|
| 采样率 / 位深 / 声道 | 48 kHz / 16 bit / 2ch（无压缩、无 ADPCM） |
| 码率 | 192 KB/s（1.536 Mbps） |
| 包长 / 包率 | 960 字节 / 200 包每秒 |
| 无线 | ESP-NOW，11Mbps 固定速率，硬件 ACK，信道 11，无加密 |
| 抖动缓冲 | 容量 48 包（240ms），稳态 15 包（75ms） |
| **设备侧延时** | **约 95ms**（队列 75 + DMA 15 + 空口/拼包 5） |
| 端到端（接 PC） | 约 120ms（再 + WASAPI 25ms + USB 2ms） |
| 稳态表现 | 连续 100 秒：欠载 0、补位 0、跳变 0、重采样 0.00%、队列稳 15 包 |
| 重采样 | 32 抽头多相窗函数 sinc，Q16 比例，稳态精确直通（零插值） |

作为对照：蓝牙 SBC/AAC 是 44.1k 有损压缩、延时 150~300ms；本条链路 48k 无损、95ms，且不依赖蓝牙协议栈的缓冲策略。

## 关键设计

### 1. 不压缩

960 字节包 = 240 帧 × 2ch × 2B，正好 5ms。压缩（ADPCM）能省带宽，但编码/解码引入的量化噪声和有损重建在安静段落能听出来，而 11Mbps 的 ESP-NOW 发 1.5Mbps 绰绰有余。**用带宽换音质，这笔交易在这个场景里是划算的。**

### 2. 重采样只在必要时工作

接收端 I2S 时钟默认跟随音源采样率，让重采样比例精确等于 1.0。此时 `src_process` 全走整数帧直取分支（每帧 2 载 2 存），**一个插值样本都不产生**。

只要比例偏离 1.0 哪怕 0.01%，包边界就得用插值顶替，残差从 −96dB 掉到 −30dB —— 小电平的钢琴、小提琴单音会发糊、发毛。这是本项目踩得最深的一个坑。

所以水位闭环有 **3.0 包死区**：队列在目标 ±3 包内一律不调，宁可少省 15ms 延时，也要让插值器彻底停下。

### 3. 水位闭环 + 相位跨包连续

收发两端晶振必然有几十 ppm 差异，队列会缓慢漂移。做法是队列深度做 EMA，偏离死区就给重采样比例加一个小偏置（P 控制，增益 8，上限 ±0.3%）。

重采样相位**跨包连续**：包尾的小数相位原样留给下一包，允许相位为负（回落到 32 帧历史区）。否则每包吸附一次整数帧，等于 200 次/秒硬跳变 —— 1kHz 只差 −44dB 听不到，10kHz 以上就是几十度相位突变。

### 4. 丢包用 PLC 复读，不用补零

丢包时重复上一包并按 1.00 / 0.60 / 0.35 / 0.20 衰减，最多 4 包。补零是波形阶跃到 0，功放会给出宽频冲击（"咔"）；复读频谱连续，大脑会自动补过去。

### 5. 其他细节

- **TPDF dither**：±1 LSB 三角分布，避免 16bit 截断的相关失真
- **2ms 交叉淡化**：断流恢复时在旧波形与新数据之间过渡
- **TX 拼包**：等满一个 5ms 包再发（最多等 30ms），半包不补零，改按 Q8 包络约 10ms 淡出
- **音量**：主机的 USB 音量请求映射到 −50~0dB（51 档），在**一包内线性插值**完成，样本级连续，拖动不滞后

## 硬件

**接收端**

| PCM5102A | ESP32-S3 |
|---|---|
| BCK | GPIO10 |
| LRCK | GPIO11 |
| DIN | GPIO12 |
| SCK | **GND**（走内部 PLL 从 BCK 恢复时钟） |
| VIN / GND | 5V / GND |

本版不输出 MCLK。若想给 DAC 更好的参考时钟，把 `ALINK_I2S_USE_MCLK` 设为 1，SCK 改接 GPIO13（12.288MHz）。

**发射端**：任意带原生 USB 的 ESP32-S3（GPIO19/20），插到主机后枚举为 `usb uac` 声卡。

两块板子都是 4MB flash、240MHz。

## 构建

```bash
# 先装 ESP-IDF v5.5（本项目用 v5.5.6 验证）
. $IDF_PATH/export.sh          # Windows: 用 idf_env.ps1 之类的激活脚本

# 接收端
cd rx_uac && idf.py set-target esp32s3 build flash

# 发射端
cd tx_uac && idf.py set-target esp32s3 build flash
```

**★ 必须改一处**：发射端的目标 MAC 是硬编码的，位置在 `tx_uac/main/alink_tx.c:159`：

```c
#define RX_MAC_ADDR  { 0x84, 0xC7, 0xBB, 0x5A, 0x73, 0x94 }
```

接收端上电时串口会打印自己的 MAC，把它填进来重新编译发射端。否则收不到（ESP-NOW 单播，不广播）。

一句话版本：**死区 3.0 是音质底线，别为了省 7.5ms 去砍它。**

## 已知限制

- **切歌偶发爆音**：音频流中断后恢复时，2ms 交叉淡化偏短，钢琴低音区可能听成一下闷响。未彻底解决。
- **单发射、单接收**：ESP-NOW 单播，没有配对流程，靠硬编码 MAC。
- **无加密**：ESP-NOW 用明文单播，同信道且知道 MAC 的设备可以抓包。
- **只支持 48kHz/16bit**：音源切换到 44.1k 时会有一小段静音（接收端要重配 I2S 时钟）。
- **当前版本只在 S3 上验证**。C3 能跑同一套算法（曾经就是 C3 上的代码移植过来的），但这一版有 4 处 S3 硬编码，未做适配。
